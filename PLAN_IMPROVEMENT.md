## 2. ПРОБЛЕМА #2 — ЛИКВИДАЦИЯ 1213 СТАБОВ (premium-насыщение)

Стабы живут в `gynChunk25–30` (1524 маркера) и `obsChunk7–27` (5754 маркера). Они перезаписывают нормальные карточки, потому что `enrichDiseases` берёт поля как есть.

### 2.1 Разделить данные на 3 слоя
1. **Verified** (врач-автор, guidelines 2025-2026) → полный blueprint.
2. **Stub** (авто-сгенерирован, помечен `editorialStatus: 'fallback'`) → НЕ показывать как «готовое».
3. **Runtime enrichment** → только безопасная обёртка, явно помеченная `needs-source-review`.

### 2.2 Волны заполнения по клиническому риску (не по порядку файлов)
- **Wave A (онко+острые):** C50–C58, D05–D07, D25–D28, D39 + острые гин/акуш (перекрут, внематочная, ПРПО, преэклампсия, кровотечения) — критично для жизни.
- **Wave B (высокий приоритет из content-roadmap):** эндометриоз, СПКЯ, миома, АМК, ВЗОМТ, рак шейки, МГТ, контрацепция, ГСД, преждевременные роды.
- **Wave C (средний):** редкие нозологии N87–N99, O85–O99.
- **Wave D (automated assist):** для низкоприоритетных — полуавтоматическая генерация черновика по `enrichDiseases` + LLM-заполнение, с пометкой `needs-source-review` для последующей верификации врачом.

### 2.3 Метрика успеха
Ввести `realContentComplete` = карточек, где ≥6 из 10 premium-полей заполнены РЕАЛЬНЫМ текстом (не маркеры стаба). Цель: 100% к концу Wave B.

## 9. КОРНЕВАЯ ПРИЧИНА (почему так вышло)

1. `audit-icd.mjs` смотрит только на наличие кода в файле → стаб с `icd: "N70.3"` засчитывается как покрытие.
2. `enrichDiseases` заполняет пустоты шаблонным текстом → на проде всё выглядит «написанным».
3. Онко/предрак не входил в `clinicallyRelevant` → целый клинический раздел не существовал.

**Гениальное решение:** не «добавить ещё карточек», а (а) сделать слепые зоны видимыми через аудит, (б) разделить verified/stub/runtime, (в) заполнять по клиническому риску, начиная с онко и острых.
